# Discordコミュニティオーナーガイド

VoxelLink Monitor は、VoxelLink に掲載した Minecraft Java サーバーを外部から定期的に確認し、障害・復旧を Discord とステータスページで知らせる仕組みです。Discordコミュニティのオーナーやモデレーターは、利用者に現在の接続状況を伝えるためのチャンネルと Bot を運用します。

このページは、Discordサーバーを管理する人向けです。VPS、Docker、Cloudflare の操作は必要ありません。

## できること

- Minecraft Java の接続確認を約60秒ごとに行う
- 単にポートが開いているかではなく、Minecraft のサーバー一覧応答まで確認する
- 障害と復旧を記録し、Discord の指定チャンネルへ通知する
- Discord の `/status`、`/uptime`、`/incidents` で利用者が状態を確認できる
- 公開ステータスページで現在の状態を表示する
- メンテナンス時間を設定し、その間の通知と障害判定を止める

監視対象は VoxelLink の掲載情報から自動で取り込まれます。サーバーアドレスや所有者を Monitor に重複入力する必要はありません。

## 最初にすること

### 1. Bot をコミュニティに導入する

Bot を追加するには、Discordサーバーで **サーバー管理** 権限が必要です。導入後、Botには少なくとも次の権限を、通知を送るチャンネルで与えてください。

- チャンネルを見る
- メッセージを送信
- アプリケーションコマンドを使う

Bot は利用者のメッセージを読む必要も、管理権限を持つ必要もありません。

### 2. VoxelLink の掲載と管理権限を確認する

掲載情報のホスト名、ポート、接続方式が正しいことを確認してください。Monitor はこの情報を使います。

掲載者の Discord アカウントが、そのサーバーの **owner** または **manager** として VoxelLink に登録されている必要があります。viewer 権限では監視設定を変更できません。

### 3. Monitor の管理画面に Discord でログインする

[VoxelLink Monitor](https://voxellink.alec-ofc.com/monitor) を開き、**Discordで管理画面へログイン** を選びます。

表示されるサーバーカードで、次を確認できます。

- 現在の状態
- 接続先とポート
- 最終確認時刻と応答時間
- 直近24時間の稼働率
- 最近の Incident（障害記録）

サーバーが表示されない場合は、VoxelLink 側でログイン中の Discord アカウントに owner または manager が設定されているかを確認してください。

### 4. Discord の通知先を設定する

サーバーカードの **Discord ステータスチャンネルID** に、通知を受けたい Discord チャンネルの ID を入力して **通知先を保存** を押します。

チャンネル ID の調べ方:

1. Discord の「ユーザー設定」→「詳細設定」を開く
2. **開発者モード** を有効にする
3. 通知先にしたいテキストチャンネルを右クリック（スマホでは長押し）する
4. **チャンネルIDをコピー** を選ぶ
5. コピーした数字を管理画面に貼り付ける

Bot に、そのチャンネルでメッセージを送信する権限が必要です。

通知チャンネルの登録は Bot のスラッシュコマンドではなく、権限確認を行えるWeb管理画面から行います。これにより、コミュニティ内の誰でも通知先を勝手に変更することはできません。

## コミュニティでの Bot の使い方

Bot を導入済みの Discord サーバーで、スラッシュコマンドを使えます。

| コマンド | 内容 |
| --- | --- |
| `/status` | 現在の状態、最終確認時刻、応答時間を表示します。 |
| `/uptime` | 直近24時間の稼働率を表示します。 |
| `/incidents` | 最近の障害・復旧記録を表示します。 |
| `/monitor` | オーナー向け管理画面を開きます。 |

通知先として設定したチャンネル内では、`/status` などは対象サーバーを自動で判断します。それ以外のチャンネルでは、コマンドの `server` に VoxelLink のサーバーIDを指定してください。

おすすめの構成は、読み取り専用に近い `#server-status` チャンネルを一つ作り、そこを通知先にする方法です。障害・復旧の自動通知と、利用者の `/status` 確認を同じ場所に集められます。

## 状態の見方

| 状態 | 意味 |
| --- | --- |
| `OPERATIONAL` | Minecraft から正常な STATUS 応答を受けています。 |
| `DEGRADED` | 接続はできますが、遅延や不安定さが検出されています。 |
| `OUTAGE` | 外部から正常な Minecraft 応答を確認できません。 |
| `MAINTENANCE` | 設定したメンテナンス時間中です。障害通知と稼働率計算の対象外です。 |
| `UNKNOWN` | Monitor 自身または監視経路に問題があり、サーバー障害とは断定していません。 |

一時的な通信揺れで通知しないよう、障害は連続3回の失敗で確定し、復旧は連続2回の成功で確定します。

## メンテナンスを予定する

管理画面の **メンテ開始（JST）** と **終了（JST）** を入力して保存します。

メンテナンス中も確認記録は残りますが、利用者には `MAINTENANCE` と表示され、障害通知は送信されません。作業終了後は自動的に通常の監視へ戻ります。

## 接続方式について

- `DIRECT`: 通常の公開 Minecraft サーバーです。
- `CLOUDFLARE_SPECTRUM`: Spectrum の公開エンドポイントを監視します。
- `CLOUDFLARE_TUNNEL`: modflared と同様に、Monitor 側の `cloudflared` クライアントで接続を試みます。

Cloudflare Access で利用者ごとのログインを必須にしている Tunnel は、掲載者の Access 資格情報を Monitor に渡す必要はありません。そのような監視できない経路は `UNKNOWN` と表示されます。

## よくある質問

### `OUTAGE` なのにポートは開いている

Monitor は TCP 接続だけでは正常と判定しません。Minecraft Java の STATUS 応答まで返せる必要があります。プロキシ設定、Minecraft サーバー本体、または STATUS を遮断するプラグインを確認してください。

### 通知が来ない

通知チャンネルIDが保存されていること、Bot にそのチャンネルへの送信権限があることを確認してください。通知は状態が変わったときだけ送られます。

### Bot はいるのにスラッシュコマンドが見えない

Bot を導入したDiscordサーバーで `applications.commands` の権限が許可されていることを確認してください。導入直後や再起動直後は、Discord側でコマンドが反映されるまで少し時間がかかる場合があります。

### VoxelLink が一時的に停止したら監視も止まる

いいえ。取り込み済みのサーバーは Monitor のデータベースに保存されるため、監視、ステータス表示、Incident、Discord 通知は継続します。VoxelLink の復旧後に掲載情報と権限が同期されます。
